# Коллекция запросов (Bruno)

Коллекция для [Bruno](https://www.usebruno.com/) — open-source API-клиента, который хранит запросы файлами прямо в git. Покрывает сквозной путь клиента, решения аналитика и негативные проверки. Сценарии, по которым её прогоняют, описаны в [`docs/test-scenarios.md`](../docs/test-scenarios.md).

## Как запустить

1. Поднять стенд: `docker compose up --build --wait` (см. корневой README).
2. Открыть Bruno → **Open Collection** → выбрать папку `api-collection/`.
3. Справа вверху выбрать окружение по логину тестовой компании. Окружение задаёт логин, ИНН, продукт, сумму, срок и ожидаемый исход.
4. Выполнять запросы папки по порядку, например через **Run folder**.

Из терминала (нужен Node.js):

```bash
cd api-collection
npx @usebruno/cli@1 run "01 Клиент" --env demo-approve
```

## Состав

| Папка | Что проверяет |
| --- | --- |
| `01 Клиент` | Вход → продукты → автозаполнение по ИНН → черновик → отправка → статус и решение → принять / подписать / дополнить данные / отозвать |
| `02 Аналитик` | Вход аналитика → очередь `MANUAL_REVIEW` → карточка → одно из четырёх решений |
| `03 Негативные проверки` | `403` для чужой роли, без CSRF и с чужого Origin, `422` для неверного ИНН, `409` для устаревшей версии, `401` без входа |

Какие запросы папки `01 Клиент` выполнять, зависит от исхода:

| Окружение | Ожидаемый исход | После запроса 09 выполнить |
| --- | --- | --- |
| `demo-approve` | `APPROVED` | 11 → 12 → 09 (до `ISSUED`) |
| `demo-term`, `demo-product` | `COUNTER_OFFER` | 11 → 12 → 09 |
| `demo-amount` | `COUNTER_OFFER` | 15 (отказ → `CANCELLED`) |
| `demo-info` | `NEEDS_INFO` | 14 → 09 (до `APPROVED`) или 13 → 14 |
| `demo-manual` | `MANUAL_REVIEW` | папка `02 Аналитик` |
| `demo-stop`, `demo-risk` | `REJECTED` | 10 (история) |
| `demo-bki` | `APPROVED` после повторов | 09 несколько раз: сначала `CHECKING` |

## Как это работает

- **Адрес:** запросы идут через nginx фронтенда `http://localhost:8080` — тот же origin, что у браузера. Бэкенд принимает изменяющие запросы только с `Origin`, равным `AUTH_ALLOWED_ORIGIN`; коллекция передаёт его из переменной `origin`. Если меняли `FRONTEND_PORT`, поправьте `baseUrl` и `origin` в окружении.
- **Авторизация:** JWT приходит в HttpOnly cookie `access_token`, Bruno хранит cookie сам. CSRF-токен запрашивается до и после входа (старый после входа недействителен) и передаётся в заголовке `X-CSRF-Token` для всех изменяющих запросов.
- **Переменные:** скрипты после ответа сохраняют `applicationId`, `revision`, `offerId`, `status` и передают их следующим запросам. `Idempotency-Key` для отправки заявки генерируется заново на каждый запуск.
- **Тесты:** каждый запрос проверяет код ответа из `docs/openapi.yaml`.
- **SSE** Bruno не поддерживает. Проверка live-статуса — через `curl -N`, см. сценарий TS-10.

## Без бэкенда: Prism

Пока бизнес-операции бэкенда отвечают `501`, коллекцию можно гонять против мок-сервера по контракту:

```bash
npx @stoplight/prism-cli@5 mock docs/openapi.yaml
```

Окружение — `prism-mock` (`http://127.0.0.1:4010`). Prism возвращает примеры из контракта, поэтому негативные проверки и цепочка статусов на нём не воспроизводятся. Он годится, чтобы проверить формат запросов.

## Как обновлять

Файлы `.bru` и окружения генерируются из `seed/companies.json` и `seed/accounts.json`:

```bash
python3 api-collection/generate.py
```

Ручные правки `.bru` перезапишутся: меняйте `generate.py`. Пароли в окружениях — тестовые значения из `seed/accounts.json`, только для локального стенда.
