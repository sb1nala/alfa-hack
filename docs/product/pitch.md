## Сценарий демо (5 минут)

**Подготовка (до выхода на сцену):**
- Стенд поднят с нуля: `docker compose down -v && docker compose up --build --wait`.
- Мок БКИ сброшен: `curl -X POST http://localhost:8001/admin/reset`.
- Два окна браузера рядом: слева — клиент (обычное окно), справа — аналитик (приватное), оба на <http://localhost:8080>, выполнен вход: `demo-approve` и `analyst`.
- Терминал с `docker compose logs -f worker` свёрнут — понадобится на шаге 5.
- Масштаб браузера 125%, уведомления выключены.

## План Б

| Что пошло не так | Что делаем |
| --- | --- |
| Стенд не поднялся / упал во время демо | Включаем запись демо (снять 25.10, файл у двух человек) и продолжаем комментировать по ней |
| Заявка «зависла» дольше 30 с | Переходим к следующему шагу с другой компанией; говорим «заявка в очереди, вернёмся» и возвращаемся в конце |
| Мок БКИ не падает на шаге 5 (счётчик не сброшен) | `curl -X POST http://localhost:8001/admin/reset` и новая заявка `demo-bki`; если не помогло — показываем на записи |
| Нет интернета | Ничего не делаем: стенд полностью локальный |
| Аналитик не видит заявку в очереди | Обновить страницу; проверить фильтр «Ручная проверка»; в крайнем случае — карточка через историю клиента |

## Вопросы жюри: заготовки ответов

| Вопрос | Короткий ответ |
| --- | --- |
| Почему скоркарта, а не ML? | Прозрачность: каждый балл объясним клиенту и аналитику, правила проверяемы тестами, а на синтетических данных модель была бы декорацией. Организаторы подтвердили, что ML не обязателен. Следующий шаг — модель рядом с правилами (challenger): не меняет решение, подсвечивает расхождения; учится на исторических данных банка. Где она встанет — `docs/architecture.md`. |
| Откуда пороги скоринга? | Экспертная политика по открытым источникам (DSCR ≥ 1,2 — стандарт рынка), версия политики фиксируется в каждом решении. Подробно — `docs/credit-policy.md`. |
| Как масштабируется? | API без состояния; worker забирает задания через `SKIP LOCKED` с арендой. Замер: 30 заявок подряд — с одним worker очередь разбирается за ≈ 20 с, с `--scale worker=3` — за ≈ 2 с. Упавший worker не теряет задание. |
| Сколько ресурсов нужно? | ≈ 260 МБ ОЗУ в простое, пик ≈ 300 МБ, без GPU; сборка с нуля ≈ 3 мин. Ноутбук с 8 ГБ — с запасом. |
| Что с безопасностью? | JWT в HttpOnly cookie, роли, CSRF + проверка Origin, Argon2id, отзыв сессии, `revision` от гонок, `Idempotency-Key` от двойной отправки, порты только на loopback. |
| Как подключить реальные БКИ/ФНС? | Моки повторяют контракт, который читает `decide()`; замена — адаптер в worker, логика решения не меняется. |
| Почему клиенту не показываем баллы? | Чтобы не обучать мошенников подбирать ответы; клиент видит причину и совет, аналитик — всё. |
| Где ИИ? | Сознательно не в MVP: ядро — объяснимые правила. В архитектуре заложены места для модели (challenger в карточке аналитика) и для LLM-ассистента на open-weights через OpenAI-совместимый API — это раздел «развитие». |
